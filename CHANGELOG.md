# Changelog

## [1.2.0] - 2026-09-29

### Изменено
- «Загрузить файл и запустить» стала «Загрузить файл»: только кладёт файл в ассет импорта,
  запуск — кнопкой «Запустить» (маршрут `/upload-to-asset` вместо `/upload-to-asset-and-start`).
  Строка «Файл импорта» — над «Ручное выполнение»: скачать шаблон → загрузить файл → запустить.

### Добавлено
- Журнал импорта для пользователей без права `application_logging`: вкладка «Логи импорта»
  показывает записи только этого импорта (`/import-log`, доступ — как на чтение конфига) вместо
  панели Application Logger, которая отдаёт журнал всего приложения. Фильтр «все / отклонённые /
  не найдены / записанные», «только последний запуск», служебные «Processing DataRow» скрыты;
  технические сообщения показаны по-человечески (причина отдельно от строки файла).
- Сводка последнего запуска во вкладке «Выполнение» (`/import-run-summary`): «записано N,
  отклонено M, не найдено K» и кнопки «Отклонённые» / «Не найдены» с окном списка.
  Запуск — записи после «Loading source data from configured source...».

## [1.1.0] - 2026-09-29

### Добавлено
- Вкладка «Выполнение» у импорта с источником «Ресурс» (`loaderConfig.type: asset`): поле
  «Файл импорта» с кнопками «Скачать шаблон» и «Загрузить файл и запустить». Файл импорта
  готовится без захода в «Ресурсы».
  - «Скачать шаблон» отдаёт ассет «<имя файла> — шаблон.<расш>» из папки рабочего файла (в нём
    можно держать инструкцию и оформление), а если его нет — xlsx, собранный из mappingConfig
    (заголовки — label колонок, лист — `interpreterConfig.settings.sheetName`). Рабочий файл
    шаблоном не отдаётся: в нём строки прошлой загрузки.
  - «Загрузить файл и запустить» проверяет расширение и наличие нужного листа, записывает файл
    в ассет по `assetPath` от имени пользователя (заметка в версии ассета — имя загруженного
    файла) и сразу запускает импорт. Пока импорт выполняется, загрузка отклоняется.
  - Доступ — как на чтение конфига (`permissions` конфига; `plugin_datahub_admin` и админ — ко всем).
  - Кнопки неактивны при несохранённых изменениях конфига: путь файла берётся из сохранённого.
- `Template\ImportTemplateBuilder` — сборка пустого xlsx-шаблона из mappingConfig; для
  переиспользования в командах приложения.

## [1.0.6] - 2026-09-29

### Исправлено
- Ошибка строки импорта в Application Logger: строку файла и причину разделяет « → ». Раньше
  последняя колонка склеивалась с текстом исключения: `…, 8500Штук в шоубоксе: …`.
- Ошибка обработки записи очереди (например, «Configuration X does not exist.») печаталась
  в Application Logger дважды подряд.

## [1.0.5] - 2026-09-23

### Исправлено
- Вкладка «Логи» конфига импорта показывается только пользователям с правом
  `application_logging`. Она построена на панели Application Logger и загружает данные сразу
  при открытии конфига, поэтому у пользователей без этого права каждое открытие давало три
  ответа 403 (`priority-json`, `component-json`, `log/show`) и три уведомления «Доступ запрещён».

## [1.0.4] - 2026-09-16

### Исправлено
- Миграция, помечающая бандл установленным, писала флаг `BUNDLE_INSTALLED__…` в scope
  `pimcore`, а не `opendxp`. Идентификатор при порте переименовали, а четвёртый аргумент
  `SettingsStore::set()` — строковый литерал — остался прежним, и свип неймспейсов его
  не увидел. `SettingsStoreAwareInstaller::isInstalled()` читает scope `opendxp`, поэтому
  бандл навсегда числился неустановленным: в админке предлагалась установка, которая на
  уже существующих правах падает дублем ключа. Обнаружено на переключении stage.

## [1.0.3] - 2026-09-15

### Исправлено
- **Восстановлены три кастомизации, потерянные при ребейзе на апстрим v1.0.1** (v1.0.0–v1.0.2
  выходили без них; они задокументированы в инвентаре `data-importer-upstream-sync`, но
  реаппляй после ребейза не выполнили):
  - `DataObjectLoader::loadByAttribute()` — всегда `getList()` с именованными условиями вместо
    магического `getBy<Attribute>()`, чья позиционная сигнатура непредсказуемо меняется в
    зависимости от локализации поля («Argument #2 ($objectTypes) must be of type ?array, int given»);
    плюс `Db::get()->quoteIdentifier()` на имя поля и поддержка `locale`.
  - `LoadDataObject` — трейлинг-слэш в пути обрезается (кроме пути `/` целиком).
  - `DataImporterHandler` — гонка воркер-маркера: `dispatch()` идёт ДО `addMessage()`, а цикл
    обработки обёрнут в `try/finally`, иначе убитый процесс оставляет осиротевший маркер и
    блокирует диспатч на всё его время жизни (по умолчанию 30 минут).

### Добавлено
- MDM-724: идентификатор тримится в `DataObjectLoader::loadByAttribute()` и
  `MultiAttributeLoadStrategy::loadElementByIdentifier()`. Выгрузки ПРОГРЕСС носят nchar-паддинг,
  а коллация колонок в MySQL 8 — `utf8mb4_0900_ai_ci`, то есть NO PAD: хвостовые пробелы в `=`
  значимы, и нетримленный идентификатор промахивается мимо существующей карточки — импорт
  считает её отсутствующей исоздаёт дубликат.
- MDM-724: строка, для которой объект не нашёлся при «Do not create», логируется как `warning`
  (было `info` — тонуло среди «imported successfully»), с идентификатором прямо в тексте.
